# Medal skills (I-146) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** complete `skill` table (163 rows: 25 real + 138 reconstructed from the wiki), real `skillExp` curve, skill
EXP after every quest, Scrooge and saves migrated, notice; tested on the bench.

**Architecture:** a generator module `server/make-skill-table.js` with `patch(dir)` (like `make-pet-tables.js`)
writes `skill.json` and `skillExp.json` into the master during `make-game-tables.js`, reading at build time the real
thethiny rows and the wiki table (Square Enix data: never in the repo). The level/EXP logic lives in
`server/medal-skill.js`; `server.js` uses it in `/stage/clear` and in a migration `migrateSkills()`.

**Tech Stack:** Node.js (CommonJS, `assert`, tests as scripts `node server/test-*.js`), Ghidra headless
(`recon/ghidra/decomp.ps1`), LDPlayer bench.

**Spec:** [docs/superpowers/specs/2026-10-18-skill-design.md](../specs/2026-10-18-skill-design.md)

## Global Constraints

- Original client unmodified: only the master, the server responses and the resources change.
- Only our own code and documentation in the repo: the real rows (thethiny) and the wiki texts are read at build time
  and end up only in `server/master_data/` (ignored by git). `server/tables/skillExp.json` (invented) is **deleted**
  from the repo: otherwise the copy of `server/tables/*` at the end of `make-game-tables.js` overwrites the real curve.
- Every row of `skill.json` has **exactly** the 35 fields of `recon/out/master_types_ww431.json["skill"]`, in the
  same order; `name` and `description` are `string(72)`: at most 71 UTF-8 bytes.
- `skillExp.json` = `[{expId, value:[a,b,c]}]` (`int[3]`), the 4 real rows of
  `D:\Progetto_Restauro_KH_UX\external\thethiny_2026-10-13\KHUx-Server\data\skillExp.json`.
- The 25 real rows keep their numbers. New `skillId`s from **1127** upward.
- Probability (verified on the real rows): `invokeProb + invokeProbPerLv * (maxLv - 1) = trigger% * 100`
  (Attack Boost I: 4000 + 80*9 = 4720 = 47%).
- `thumbId` only 1-5 (original icons `img/skill/Skill_Icon1-5.png`).
- Medals already saved without a skill stay without one; Scrooges already owned keep today's skill; skills already
  saved keep the level shown.
- Every difference from the original goes in the Notices, in English.
- Skill sources in the masters (spec 5.4: `stage.clearGetAssignSkill*`, `reward.assignSkill*`, `mission`, ...): today
  all the `*SkillId`s of our masters are 0, so there is no code to write; Task 6 Step 8 notes it in
  `medaglie.md` (they activate when a master has some).
- Commits in Italian with `git -c safe.directory=* commit -F <file>`, UTF-8 without BOM, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; `git pull --rebase` and push at every task.
- Bench: only one script at a time; taps only while the game is alive; SKIP on every dialogue.

## Review Focus

- Wiki descriptions longer than 71 bytes or with markup (`<br>`, `''...''`, `{{...}}`): they must be cleaned up and
  shortened, never truncated in the middle of a UTF-8 character (the client reads `string(72)`). Test in Task 2.
- `getPoint.exp` missing, non-numeric or negative (old story quests, `/stage/retire`): no EXP, no
  crash. Test in Task 3.
- Skill already at max level: the EXP does not exceed the max threshold and the level does not go above `maxLv`. Test in
  Task 1 and Task 3.
- Deck medal with a `skillId` no longer present in the master (old rows): `medalSkillOf` already discards it;
  the EXP must not create an entry for it. Test in Task 3.
- Migration run twice (server restart): idempotent, `skillVersion` at 1. Test in Task 4.
