# Layout originali dai dati JP 4.3.1 (thethiny) al posto dei nostri generati: import_jp_coco.py
# (lanciato da build-resources.ps1 dopo make_layouts/make_textures). I-117,
# docs/notes/risorse_layout.md#jp-originali.
#
# Una riga = un layout radice (con la sua chiusura: sotto-layout delle scene, texture).
# Togliere (o commentare) una riga = al build successivo torna il layout generato.
# Opzioni dopo il nome:
#   rev=N        revisione JP fissata (0 = file senza suffisso; predefinita: entry id piu' alto)
#   need=a,b     widget che il codice cerca senza controllo: se l'originale non li ha, la radice si ferma
#   +absent-ok   texture assenti ovunque tollerate (mai con il 9-slice: quello ferma sempre)
#   graft=a,b    solo per un layout WW servito: innesta i widget a, b della revisione JP (rev=) sotto lo
#                stesso genitore, il resto resta WW (eccezione alla regola dei nomi serviti)
# «? Nome  # motivo» = da decidere: non si importa, compare solo nel rapporto.
#
# Controllo fatto il 13-10-2026 (jp_coco_widgets.py sul decompilato attorno ai caricatori,
# widget_lookup.py; commenti di make_layouts.py; classi dei widget): per le righe attive
# l'originale ha i widget che il codice cerca, o il codice li controlla (null) prima di usarli.
